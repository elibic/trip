# 🏕️ טיול משפחות

אפליקציה לתכנון טיול של כמה משפחות יחד — מי מביא מה, לאן הולכים ומתי, מי אחראי על כל ארוחה, וכמה כל אחד שילם.

- **🎒 ציוד אישי** — מה שכל משפחה מביאה לעצמה, עם סימון נפרד לכל משפחה. אפשר לסמן פריט כ**פרטי** כך שרק המשפחה שרשמה אותו רואה אותו.
- **🤝 ציוד לכולם** — פריטים שמשפחה אחת לוקחת עליהם אחריות עבור כולם ("אנחנו נביא!").
- **🛒 קניות** — רשימת קניות משותפת עם כמויות, וכפתור "אנחנו נקנה" שבו כל משפחה לוקחת על עצמה מוצרים. מסמנים ✓ כשקונים, מה שנקנה יורד לתחתית הקטגוריה, ויש סרגל התקדמות. מוצר שנקנה מקבל כפתור **"📦 לציוד"** שמעביר אותו ל"ציוד לכולם" — כי אחרי שקנו צריך גם לזכור לקחת. אפשר גם להעביר את כל מה שנקנה בבת אחת. הקטגוריה נשמרת במעבר (מוצר בלי קטגוריה נכנס ל"אוכל"), הכמות נשמרת כהערה, והמשפחה שקנתה נרשמת כאחראית. הפריט מקבל בציוד תגית **"🛒 נקנה"**, ובסיכום הקניות מוצג כמה מוצרים כבר עברו — לחיצה עליו קופצת לרשימת הציוד.
- **🗺️ מסלול** — עצירות לכל יום עם שעות, הערות וכפתורי ניווט ל-Waze ולמפות גוגל, ומאגר **רעיונות** למקומות שעוד לא שויכו ליום — משבצים אותם ליום בלחיצה, ואפשר גם להעביר עצירה בין ימים. **הוספת עצירה או רעיון פותחת ישר את המפה** עם המקומות שבאזור — אפשר לחפש מקום בשמו, לגלות מה יש בסביבה לפי קטגוריה (אוכל, חופים, מעיינות, פארקים, אטרקציות, מתקני משחקים, קמפינג ועוד), ללחוץ "📍 סביבי" למקומות קרובים אליכם, או פשוט לכתוב ולהוסיף כטקסט חופשי כשהמקום לא נמצא במפה. עצירה עם מיקום מסומן מקבלת ניווט מדויק, ולכל יום יש קישור "מסלול היום" שפותח בגוגל מפות את כל העצירות ברצף.
- **🍽️ ארוחות** — שיבוץ משפחה אחראית ותפריט לכל ארוחה בכל יום.
- **💰 הוצאות** — רישום הוצאות והתחשבנות אוטומטית: מי מעביר למי בסוף הטיול.

בכל הרשימות: שורת ההוספה נמצאת **בראש הרשימה** (כותבים ולוחצים Enter, אפשר להמשיך לפריט הבא בלי שהשדה יזוז), ויש **כפתור ＋ צף** שקופץ אליה מכל מקום.

**העברה בין הרשימות:** לחיצה על ⋯ בשורה פותחת רצועה קומפקטית עם שלושת היעדים — 🎒 ציוד אישי, 🤝 ציוד לכולם, 🛒 קניות — והקשה אחת מעבירה. באותה רצועה גם עריכה ומחיקה. העברה נחסמת אם הפריט כבר קיים ביעד.

**הגנה מכפילויות:** פריט שכבר קיים ברשימה לא נכתב פעמיים — מוצגת הודעה והשורה הקיימת מודגשת. ההשוואה מתעלמת מרווחים מיותרים ומהבדלי גרשיים, ועובדת גם כשמדביקים רשימה שלמה. שתי רשימות הציוד נבדקות בנפרד, כך שאותו שם יכול להופיע גם באישי וגם במשותף.

**עבודה לפי קטגוריות:** ליד כל כותרת קטגוריה יש ＋ שמתחיל הוספה ישר אליה — שורת ההוספה מציגה "מוסיפים ל: מטבח" וכל מה שנכתב אחר כך נכנס לשם, עד שמשנים או לוחצים ✕. לשינוי קטגוריה של פריט קיים מקישים על התג שבשורה שלו, ונפתחת רצועת קטגוריות קטנה בתוך השורה — מחליקים הצידה ומקישים.

הכל מתעדכן **בזמן אמת** אצל כולם, בלי הרשמה ובלי סיסמאות: שולחים קישור בוואטסאפ, כל אחד בוחר את המשפחה שלו — וזהו. אפשר (ומומלץ) להתקין את האפליקציה על מסך הבית של הטלפון.

## הקמה חד-פעמית (כ-5 דקות, חינם)

האפליקציה עצמה מתארחת ב-GitHub Pages, והנתונים נשמרים ב-Firebase של גוגל (במכסת החינם — יותר ממספיק לכמה משפחות). צריך להקים פרויקט Firebase פעם אחת:

### שלב 1: יצירת פרויקט Firebase

1. היכנסו אל [console.firebase.google.com](https://console.firebase.google.com) (עם חשבון גוגל).
2. לחצו **Create a project** (או "הוספת פרויקט") → תנו שם, למשל `family-trips` → אפשר לבטל את Google Analytics → **Create project**.

### שלב 2: יצירת מסד נתונים

1. בתפריט הימני/שמאלי: **Build → Realtime Database** → **Create database**.
2. מיקום: בחרו `europe-west1 (Belgium)` (הקרוב לישראל) → **Next**.
3. בחרו **Start in locked mode** → **Enable**.

### שלב 3: חוקי אבטחה

1. בעמוד ה-Realtime Database, עברו ללשונית **Rules**.
2. מחקו את מה שכתוב שם והדביקו במקומו:

```json
{
  "rules": {
    ".read": false,
    ".write": false,
    "tripsIndex": { ".read": true, ".write": true },
    "trips": { "$tripId": { ".read": true, ".write": true } }
  }
}
```

3. לחצו **Publish**.

### שלב 4: חיבור האפליקציה

1. לחצו על ⚙️ (ליד "Project Overview") → **Project settings**.
2. גללו למטה אל **Your apps** → לחצו על אייקון ה-Web **`</>`**.
3. תנו כינוי (למשל `trip-app`), **בלי** לסמן Firebase Hosting → **Register app**.
4. יוצג לכם בלוק קוד עם `firebaseConfig = { ... }` — העתיקו אותו.
5. פתחו את הקובץ [`js/firebase-config.js`](js/firebase-config.js) במאגר הזה והדביקו לפי הדוגמה שבתוך הקובץ (מחליפים את ה-`null`).

> ⚠️ **חשוב:** ודאו שבאובייקט יש שורת **`databaseURL`**. בקונסולות חדשות היא לפעמים לא מוצגת — במקרה כזה העתיקו את הכתובת מהכותרת של עמוד ה-Realtime Database (נראית כמו `https://family-trips-xxxx-default-rtdb.europe-west1.firebasedatabase.app`) והוסיפו אותה בעצמכם. בלעדיה האפליקציה לא תתחבר.

### שלב 5: פרסום ב-GitHub Pages

1. במאגר ב-GitHub: **Settings → Pages**.
2. תחת **Source** בחרו **Deploy from a branch** → Branch: `main`, תיקייה `/ (root)` → **Save**.
3. תוך כדקה האפליקציה תעלה לכתובת: **`https://<שם-המשתמש>.github.io/trip/`**

זה הקישור ששולחים לקבוצת הוואטסאפ 🎉

## 📲 התקנה על הטלפון

האפליקציה מציעה זאת בעצמה, אבל אפשר גם ידנית:

- **אנדרואיד (Chrome):** תפריט ⋮ → "הוספה למסך הבית" / "התקנת אפליקציה".
- **אייפון (Safari):** כפתור שיתוף ⬆️ → "הוסף למסך הבית".

לאחר ההתקנה האפליקציה נפתחת במסך מלא עם אייקון משלה — כמו כל אפליקציה.

## 🔒 מה עם אבטחה?

- אין צורך בסיסמאות: כל טיול מקבל מזהה אקראי ארוך שלא ניתן לניחוש, ורק מי שקיבל את הקישור מגיע אליו.
- מפתחות ה-Firebase שבקובץ הקונפיגורציה הם מזהים ציבוריים — זה בסדר גמור שהם במאגר. ההגנה נקבעת ע"י חוקי האבטחה משלב 3.
- **על פריטים פרטיים בציוד:** פריט המסומן כפרטי מוסתר משאר המשפחות באפליקציה, אבל הוא עדיין נשמר במסד הנתונים המשותף. זו הסתרה נוחה מהעין ולא הצפנה — אל תשמרו שם מידע רגיש באמת (סיסמאות, מספרי כרטיס אשראי וכדומה).
- רוצים הקשחה נוספת בעתיד? אפשר להפעיל Anonymous Authentication ב-Firebase ולשנות את החוקים ל-`"auth != null"` — אבל למקרה של קבוצת משפחות זה בדרך כלל מיותר.

## 📣 הודעה חיה לכל המשפחות

הדף [`admin.html`](admin.html) (בכתובת `https://<שם-המשתמש>.github.io/trip/admin.html`) שולח הודעה שמוקפצת **מיידית בכל מכשיר שהאפליקציה פתוחה בו, בלי שאף אחד יצטרך לרענן**. זה עובד כי כל מכשיר כבר מחזיק חיבור חי ל-Firebase, וההודעה נכתבת לענף שכולם מאזינים לו.

- כותבים כותרת ותוכן, ואופציונלית מסמנים "להוסיף כפתור רענון ועדכון" — כדי שכולם יעברו לגרסה חדשה בלחיצה אחת.
- ההודעה מופיעה פעם אחת לכל מכשיר; הודעה חדשה (עם מזהה חדש) תופיע שוב אצל כולם.
- אחרי שכולם ראו, כדאי ללחוץ "מחיקת ההודעה".
- הדף אינו מוגן בסיסמה ואינו מקושר מהאפליקציה — כמו כל שאר הנתונים, מי שיודע את הכתובת יכול להשתמש בו.

## 🔄 עדכוני גרסה

כשמעלים שינוי לאפליקציה, כל מי שפתח אותה מקבל חלון "יש גרסה חדשה!" עם רשימת השינויים וכפתור שמבצע רענון מלא (מסיר את ה-Service Worker, מנקה את כל המטמון וטוען מחדש מהרשת). כך כולם עובדים על אותה גרסה. בתחתית מסך הבית יש גם קישור "בדיקת עדכון ורענון" לשימוש ידני בכל רגע.

**איך מוציאים גרסה חדשה** (לתשומת לב מי שעורך את הקוד):

1. לעדכן את `version` ואת רשימת `changes` בקובץ [`version.json`](version.json) — זה מה שהמשתמשים יראו בחלון.
2. לעדכן את אותו מספר גרסה גם ב-[`js/version.js`](js/version.js) — זו הגרסה שרצה בדפדפן, וההשוואה בין השתיים היא שמפעילה את ההודעה.
3. לדחוף ל-branch שממנו מתפרסם GitHub Pages. תוך דקות כל המשפחות יקבלו את ההודעה.

## 🗺️ על חיפוש המקומות

חיפוש המקומות עובד **בלי מפתח API ובלי חשבון בתשלום**:

- **חיפוש לפי שם ולפי אזור** — דרך Nominatim של OpenStreetMap (שירות חינמי ופתוח).
- **"מה יש באזור"** — דרך Overpass API, שמחזיר מקומות אמיתיים מתוך מפת OpenStreetMap לפי קטגוריה, ברדיוס 5 ק"מ מהאזור שחיפשתם.
- **תצוגת המפה** — מפת גוגל מוטמעת, וכל מקום ניתן לפתיחה בגוגל מפות או בוויז בלחיצה.

השירותים האלה מוגבלים בקצב שימוש הוגן (בקשה בכל פעם שלוחצים חיפוש), מה שמתאים בדיוק לשימוש כזה. אם בעתיד תרצו את מנוע החיפוש של גוגל עצמו (Google Places), הוא דורש מפתח API עם חשבון חיוב בגוגל קלאוד — כלומר כרטיס אשראי, גם אם בפועל לא משלמים.

## 🛠️ טכנולוגיה

HTML/CSS/JavaScript נקי (בלי build), Firebase Realtime Database לסנכרון חי, PWA מלא (מתקין, עובד במסך מלא). כל הקוד בתיקייה הזו — אפשר לערוך ולהעלות, ו-GitHub Pages מתעדכן אוטומטית בכל push.
