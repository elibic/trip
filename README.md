# דנדשמש

**רק דנדש. רק בבית שמש.**

לוח מוצרים חדשים שלא התאימו, לבית שמש בלבד. הזמנתם מאתר בארץ או בחו"ל, המוצר הגיע ולא התאים, וההחזרה לא שווה את הטרחה? מפרסמים כאן, ושכן מהשכונה בא לאסוף ברגל.

> הזמנתם נעל ב-Next והמידה לא מתאימה? אל תורידו את הטיקט! כנסו לדנדשמש - מישהו בעיר מחפש בדיוק את זה.

השם והסלוגנים יושבים ב-`js/i18n.js`, הלוגו ב-`icons/logo.svg`.

## מה יש באפליקציה

- **פיד** עם סינון לפי קטגוריה, למי, גיל, מצב, מקור קנייה, שכונה, וחינם בלבד. חיפוש טקסט שמבין עברית: "שמלה" מוצא גם "שמלת" ו"השמלה". מודעות מקודמות מופיעות ראשונות.
- **פרסום** עם עד 4 תמונות שנדחסות בטלפון לפני ההעלאה, מידה כפי שכתובה על המוצר, סוג הבעיה ותיאור חופשי, מחיר מבוקש ומחיר מקורי, קישור למוצר, שכונה, ודרכי קשר: הודעה במערכת, טלפון (עם וואטסאפ) ומייל.
- **תרגום אוטומטי**: כל מודעה מתורגמת פעם אחת בזמן הפרסום, המפרסם רואה את התרגום ומתקן לפני שליחה, והקוראים רואים אותה בשפת הממשק שלהם עם "הצג מקור".
- **ממשק דו-לשוני** עברית ואנגלית, עם החלפה בכפתור. מצב בהיר וכהה.
- **מחפשים**: פוסט אחד פעיל לכל אחד, ל-14 יום, בשורה אחת. מי שיש לו את המוצר לוחץ "יש לי את זה" ונפתחת שיחה. מי שמפרסם מוצר מקבל רמז כשמישהו מחפש משהו דומה.
- **הודעות** בתוך האפליקציה, חיות, עם מונה הודעות שלא נקראו.
- **חיפושים שמורים**: שומרים סינון, ומקבלים סימון בלשונית "שלי" על כל מוצר חדש שמתאים.
- **מחזור חיים**: כל מודעה בתוקף 30 יום. 3 ימים לפני הסוף מופיעה תזכורת עם כפתור חידוש. בלי חידוש היא עוברת לארכיון ונשארת אצל המפרסם לפרסום מחדש. סטטוסים: פנוי, שמור, נמכר.
- **דיווח** על מודעה או על פוסט.
- **דף ניהול** (`admin.html`): מספרים, תור דיווחים, הסתרה והחזרה של מודעות, קידום לראש הפיד ל-3 עד 30 יום, מחיקה, חסימת משתמשים, עריכת רשימות השכונות ומקורות הקנייה, ניהול רשימת המנהלים, וכפתור תחזוקה.
- **PWA**: מתקינים על מסך הבית, נפתח כמו אפליקציה, ויש הודעה כשיוצאת גרסה חדשה.

צפייה פתוחה לכולם. פרסום, הודעות ופרטי קשר דורשים התחברות, בלי סיסמאות: חשבון גוגל או קישור שנשלח למייל.

## למה זה לא עולה כסף

הכל רץ על Firebase בתוכנית החינמית (Spark), שלא דורשת כרטיס אשראי.

| מה | איפה | המכסה החינמית |
|---|---|---|
| אירוח האתר | Firebase Hosting או GitHub Pages | 10GB תעבורה בחודש |
| מסד נתונים | Firestore | 1GB אחסון, 50,000 קריאות ו-20,000 כתיבות ביום |
| תמונות | בתוך Firestore, דחוסות בטלפון | כ-2,500 מודעות עם תמונות בבת אחת |
| התחברות | Firebase Authentication | ללא הגבלה מעשית |
| תרגום | MyMemory | 5,000 תווים ביום, 50,000 עם מייל ב-`js/config.js` |

כמה הערות על הגבולות:
- **תמונות**: Firebase Storage דורש היום כרטיס אשראי בפרויקט חדש, לכן התמונות נשמרות כטקסט דחוס בתוך Firestore. תמונה ממוצעת שוקלת כ-80KB. כפתור התחזוקה בדף הניהול מוחק מודעות שבארכיון יותר מ-90 יום, וכך האחסון לא מתמלא.
- **קריאות**: עמוד פיד הוא 24 קריאות. 50,000 ביום הם בערך 2,000 טעינות פיד ביום. האפליקציה שומרת עותק מקומי, אז ביקור חוזר עולה פחות.
- **תרגום**: אם המכסה היומית נגמרת, המודעה מתפרסמת בשפת המקור, והקוראים מקבלים כפתור "תרגום" שפותח את Google Translate.
- כשהאתר יגדל מעבר לזה, המעבר לתוכנית Blaze הוא בתשלום לפי שימוש, והקוד לא משתנה.

## הקמה (פעם אחת, כרבע שעה)

### 1. פרויקט Firebase

1. היכנסו ל-[console.firebase.google.com](https://console.firebase.google.com) ולחצו **Create a project**. מומלץ פרויקט חדש ונפרד מאפליקציות אחרות. Google Analytics לא נחוץ.
2. **Build > Firestore Database > Create database**. מיקום: `eur3 (europe-west)` או `europe-west1`. מצב: **production mode**.
3. **Build > Authentication > Get started > Sign-in method**:
   - הפעילו **Google**.
   - הפעילו **Email/Password**, ובתוכו את **Email link (passwordless sign-in)**.
4. ⚙️ **Project settings > Your apps > Web `</>`**. תנו כינוי, בלי Firebase Hosting בשלב הזה, ולחצו **Register app**. העתיקו את האובייקט `firebaseConfig` אל [`js/config.js`](js/config.js) במקום ה-`null`.

### 2. המנהל הראשון

במסוף, ב-**Firestore Database > Data**:
1. **Start collection** בשם `config`.
2. Document ID: `admins`.
3. שדה בשם `emails`, סוג **array**, ובתוכו ערך מסוג **string**: כתובת המייל שלכם, באותיות קטנות.

מכאן והלאה מוסיפים מנהלים מתוך דף הניהול. כתובות המנהלים לא כתובות בקוד, ולכן המאגר יכול להיות ציבורי.

### 3. העלאה

צריך Node.js במחשב.

```bash
npm install
npx firebase login
npx firebase use --add      # בוחרים את הפרויקט מסעיף 1
npm run deploy              # חוקי אבטחה, אינדקסים, והאתר עצמו
```

האתר עולה לכתובת `https://<project-id>.web.app`, והיא כבר מאושרת להתחברות.

**רוצים GitHub Pages במקום?** מפעילים Pages במאגר כמו באפליקציית הטיול, מריצים רק `npx firebase deploy --only firestore` בשביל החוקים והאינדקסים, ומוסיפים את הכתובת `<user>.github.io` ב-**Authentication > Settings > Authorized domains**. בלי השלב הזה ההתחברות תיכשל עם `auth/unauthorized-domain`.

### 4. בדיקה

1. נכנסים לאתר, מתחברים, ומפרסמים מוצר ניסיון.
2. נכנסים ל-`admin.html` ומוודאים שרואים את המספרים.
3. אם הפיד מציג שגיאה על index: האינדקסים נבנים כמה דקות אחרי הפריסה. עד אז האפליקציה עוברת לבד לשאילתה פשוטה ומסננת מקומית.

## תחזוקה שוטפת

- **פעם בשבוע**: דף הניהול > סקירה > **הרצת תחזוקה**. מעביר לארכיון מודעות שפג תוקפן, מוחק מודעות שבארכיון יותר מ-90 יום, ומנקה פוסטים ישנים ב"מחפשים".
- **דיווחים**: מופיעים בלשונית "דיווחים" בדף הניהול, עם כפתורי הסתרה, חסימה וסגירה.
- **שכונות ומקורות**: נערכים בדף הניהול. פריט שכבר בשימוש מסתירים ולא מוחקים, כדי שמודעות ישנות ימשיכו להציג אותו.

## גרסה חדשה

1. מעדכנים את המספר ב-[`js/version.js`](js/version.js) ואת אותו מספר ורשימת השינויים ב-[`version.json`](version.json).
2. `npm run deploy` (או push, אם האתר על GitHub Pages).
3. מי שהאפליקציה פתוחה אצלו מקבל חלון "יש גרסה חדשה" עם כפתור רענון.

## פיתוח ובדיקות

הכל HTML, CSS ו-JavaScript נקיים, בלי שלב בנייה. הבדיקות רצות על האמולטורים של Firebase, בלי רשת ובלי לגעת בנתונים אמיתיים.

```bash
npm install
npm run dev                       # אמולטורים של Firestore ו-Auth
node tests/server.mjs             # בחלון שני; פותחים http://localhost:5173/?emu=1
```

```bash
npm test                          # הכל
npm run test:unit                 # חיפוש ועיבוד טקסט
npm run test:rules                # 18 בדיקות של חוקי האבטחה
npm run test:e2e                  # 30 צעדים בדפדפן: שני משתמשים, פרסום, הודעות, ניהול
```

בדיקת ה-e2e צריכה Playwright עם Chromium, ושומרת צילומי מסך ב-`tests/shots/`.

## אבטחה ופרטיות

- חוקי האבטחה סוגרים הכל ופותחים רק את מה שצריך. כל חוק מכוסה בבדיקה ב-`tests/rules.test.mjs`.
- אי אפשר להתחזות למפרסם, לקדם מודעה בעצמך, להאריך תוקף מעבר ל-30 יום, לנפח צפיות, או להחזיר מודעה שהנהלה הסתירה.
- טלפון ומייל של מפרסם נשמרים בנפרד מהמודעה, ונגישים רק למשתמשים מחוברים.
- הודעות נגישות רק לשני הצדדים בשיחה.
- רשימת המשתמשים, הדיווחים ורשימת המנהלים נגישות רק למנהלים.
- מנהל מזוהה לפי כתובת מייל מאומתת בלבד.

## מה עוד לא כאן

- **התראות פוש** לטלפון על מוצר חדש בחיפוש שמור או על הודעה. היום הסימון מופיע בתוך האפליקציה. פוש דורש שרת קטן שרץ ברקע, ונוסיף אותו כשיהיו כ-50 מודעות אמיתיות.
